# vesper 跟跑教程

这批教程跟着 vesper 已完成的真实工序走，从空仓库搭出一个消费 visor 的单色桌面壳：先在借来的树上立起骨架，fake session host 当进程内战场，最小桌面画出第一行字，然后第一扇窗口学会拖动与关闭，图标与双击把「桌面是启动器」的第一块砖放上屏，PBM 解码器让墙纸从文件里来，终端控件先吃回环假源再接真 bash，借壳从环境变量固定成 git 子模块，fbdev 与 evdev 把桌面送上裸机，QEMU 彩排用串口标记加截屏像素断言验收，画布升到 XRGB8888、主题换了暮金，第一个子程序经私有通道成窗，随后合成器主线开工，libwayland-server 内嵌进桌面、xdg toplevel 生命周期全链可判，输入座位与窗管理接进窗口框，帧回调按桌面节拍走、缓冲合成即释放，XWayland 桥让 X 程序与原生窗口同层，第四口 spawn 让子进程带着干净的环境出生，终端件迁库成真程序、桌面图标拉起真进程，注册表与图标列立起启动器，最后窗口缩放把尺寸下发与 SIGWINCH 接通，终端换格重切。正文把实现与测试写成成对推进的过程。每章收尾有一个可以自己执行并观察结果的验收。

写法上沿用 visor 教程的口径：按仓库当时的工序走，CMake 与代码逐段读，被工具逮住的错误写成你会亲历的过程，不追认「本来就该这样」。

## 读者需要什么底子

会 C++ 基本语法，见过模板，就够了。概念与机制用到时当场解释，不要求先修。要会用命令行，CMake 与 CTest 的命令逐条给出普通写法。

建议先读过 [visor 的跟跑教程](../../third_party/visor/document/tutorials/README.md) 或至少熟悉它的词汇（几何、画布、宿主表、控件树、脏区）。本教程会用到那些概念，用到时给一句白话，但不再从零讲。

手边要有一台 Linux（或 WSL）机器：支持 C++23 的编译器、CMake 3.28 以上、Ninja。clang-format、clang-tidy 是可选工具，装了才有对应目标，不装不影响构建与测试。裸机彩排那两章还要 QEMU 加 KVM。

## 读完能得到什么

一个你自己一步步搭出来的仓库：可构建、可测试、可差分验证的桌面壳，从最小桌面一直通到 Wayland 合成器、XWayland 与真终端进程。

一套可迁移的做法：

- 借壳不砍树：别人的工程整树借用，自己的目标直接编译它的源文件，不动它一个字节，缺件回上游提。
- 会话替身先于真宿主：进程内的 fake host 从第一天就是判例战场，逐次区域日志让「新旧两框都重画了」这类主张有边界侧的证人。
- 字面断言：像素值、区域矩形写死在测试里，期望不是算出来的另一份实现。
- 一个像素一个像素读回来：判断画对了没有，最终证据是宿主帧里的位，不是控件自己报的说法。
- 验收是一道闸：rel、ASan/UBSan、TSan、format、tidy 五道，任一步失败即停，实弹彩排单列。
- 桌面语义与输入事实分家：窗口、拖动、摆放归桌面，六种事件、捕获、焦点归框架，两边的接口从第一天就是真边界。
- 进程边界以接口形状先行：窗口递像素、桌面递事件这条边先是进程内接口，换真进程时桌面结构不推倒重来。
